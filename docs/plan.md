# Plan

### Problem breakdown and why the approach was taken

| Step               | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Project foundation | Create the monorepo scaffolding and docker containers for the planned architecture, ensuring a clean working starting point. This gives us a solid starting point and planned structure to help with the Agentic development so that all files are properly split and structured                                                                                                                                                                                                                                                                               |
| Data layer & SQL   | Design and migrate the schema for the initial article database (leaving out enrichment for now). Research, understand and add the indices and tooling required to fulfil the requirements. This will prepare the data for filtering and boolean search, which is probably the main feature of this assignment.                                                                                                                                                                                                                                                 |
| Boolean search     | Develop a Boolean search parser for the FE and BE to validate the boolean search, map to a syntax tree. Then create a mapper to translate the AST to PostgreSQL tooling, using text search querying.                                                                                                                                                                                                                                                                                                                                                           |
| LLM enrichment     | While agentic development on other areas is running, start researching LLM model costing and solution. Cheap vs Thinking, single vs multiple models, self-hosted on CPU/GPU servers vs LLM APIs.<br><br>Then setup the necessary migrations for a table to store the article enrichment and link up with the sleected LLM.<br>Also add a simple mocker in case LLM is not available. Note that we will not be creating any job queuing (Depending on time), instead we will run a script that will enhance the seeded articles, while still being queue-ready. |
| Fullstack surface  | UI will be handled with each step, to see that the developed features are actually working, avoiding setting up Postman to test over API. We will then go over the UI at the end, add the aggregation chart and ensure all expected filters and requirements are met.                                                                                                                                                                                                                                                                                          |
| Responsible coding | This will be followed throughout, however at the end we will conduct a code review, focusing on security scanning to ensure we do not have any potential threats within our code that can be exposed.                                                                                                                                                                                                                                                                                                                                                          |

### What I'd cut under time pressure

- Since it was not mentioned, the first likely element to remove would be the job queue. This would be used to handle live ingress of articles along with the genration of the enrichment data.

- As per the assignment specs, if pressed for time or presented with third party issues from the provider, we would mock the LLM reponses for enrichment, hardcoding the enrichments while processing them through LLM chat instead, seeding the enrichments same as the articles.

- Limit the amount of filtering capabilities on the aggregators and search. Handle 1 or 2 filters to show how we would index our data and handle the filtering, while avoiding doing it for multiple parameters.
